# «Городок у реки» для Windows

Игра из `prototypes/app`, упакованная в приложение (Electron) с установщиком.

## Сборка

```
cd desktop
npm ci
npm start            # запустить приложение (собирает web/index.html)
npm run installer    # dist/Gorodok-Setup-<версия>.exe
npm run smoke        # проверка: запуск, сохранения, старое сохранение
```

Установщик собирает `scripts/make-installer.mjs`: electron-builder упаковывает приложение,
иконка и версия записываются в `Gorodok.exe` библиотекой resedit, установщик — NSIS по
`installer.nsi` (нужен `makensis`: на Windows — NSIS, на Linux — пакет `nsis`; Wine не нужен).
На каждый push GitHub Actions собирает установщик на Windows и запускает проверку
(`.github/workflows/windows-installer.yml`), готовый `.exe` — в артефактах запуска.

Версия игры — `version` в `package.json`. Новая версия ставится поверх старой.

## Сохранения

- Файлы `%APPDATA%\Городок у реки\saves\<id>.json`: `save-…` — сохранения игрока,
  `auto-1…3` — автосохранения (раз в 2 минуты и при закрытии окна).
  Папка игры и папка сохранений разные: обновление и удаление игры сохранения не трогают.
- Запись атомарная (временный файл → переименование). Удалённое сохранение и файл,
  перезаписанный другой версией формата, уходят в `saves\backups`.
- Формат и миграции — `prototypes/app/saves.js`. В файле записаны `schema` (версия
  формата) и `app` (версия игры). Старая схема при загрузке проходит шаги миграции
  по порядку; сохранение более новой схемы игра не открывает и не перезаписывает.
- Правило для разработки: меняется то, что лежит в сохранении, — `SCHEMA` + 1, шаг в
  `MIGRATIONS`, образец старого сохранения в `prototypes/app/test/fixtures` и тест
  (`node --test prototypes/app/test/*.test.mjs`).
